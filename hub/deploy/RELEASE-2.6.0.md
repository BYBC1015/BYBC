# Hub 2.6.0：真实交接对话与按任务并行

原执行器把所有专业任务放在同一个顺序循环中，即使是独立交付也需要等待。此次改为持久化的任务执行池：默认同时处理两项独立工作，总控使用独立通道。同一智能体可在不同对话并行执行；角色、对话、任务、设备继续分别管理。

## 用户可见的变化

- 总控安排工作后，原对话可看到负责人和具体要求。执行者可以针对范围、细节或矛盾发起真实问题，由总控实际答复，消息自动更新，无需刷新。
- 交接默认最多两轮，总控设置可改为 0–10 轮。明确的工作不需要为了轮数刻意追问；双方不能伪造对方发言。
- 等待交接时，执行者结束本轮并释放执行位置。答复后继续原任务，已取消工作不会被迟到消息重新启动；答复失败会显示阻塞，后续实际答复可恢复。
- 独立工作分别保存目录和执行记录。现有共享工程保持顺序执行；外部时间线、文件等通过一致的资源名称保护。取消、离线和超时不会直接释放仍可能正在写入的资源。
- 修改任务在开工时接入原工作的成果文件，包括排队期间才产出的文件，便于后续预览和继续处理。

## 验证范围

回归覆盖同一身份的独立任务进程重叠、同一工程顺序执行、跨设备共享资源互斥、交接轮数与过期凭据、丢失回执恢复、取消与迟到答复、失败交接恢复、成果接续以及浏览器自动显示交接并保留输入草稿。执行测试使用真实本地子进程和实际服务接口，不要求付费模型随机回答作为测试断言。

轮数控制、幂等与资源约束由程序保证；问题是否有价值、任务范围和资源名称是否完整仍取决于总控与执行者判断。在线设备断联且旧进程状态不明时保留待核对状态，避免重复生产。

本版是服务器与本地执行器更新，不包含新的桌面或移动端安装包。安装包镜像发布约定保持不变。公开源码备份不包含运行配置、密钥、工作数据库、会话或用户附件。
