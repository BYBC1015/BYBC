# 七个智能体的分工与派工约定

智能体是持续存在的执行身份，不等于设备、模型或对话。总控负责按本次交付选择角色；每项交付只有一位负责人。

| 角色 | 负责 | 边界 |
| --- | --- | --- |
| 总控 | 需求、验收标准、拆分交付、模型与人员分配、调整和冲突处理 | 简单交流直接回答；不重复承包制作，不增加审批岗 |
| Hub 工程师 | 代码、功能、测试、部署、设备、环境、CLI/MCP/API 接入与缺失配置 | 不包办美术方向或图片制作 |
| 美术总监 | 风格方向、审美标尺、关键视觉评议 | 不重复制作，不作为每个任务的审批关卡 |
| 锦衣卫 | 查找项目相关优秀案例，优先最近一年；核验来源与日期，提炼可借鉴点 | 不替美术总监定风格，不承包制作、后期或工程；已有参考研究先复用 |
| 视觉制作师 | 图片生成与修图、UI 视觉稿、版式、海报、封面、视频源素材 | 网页实现交工程师，已有视频工程处理交后期 |
| 后期技术师 | 码素材、字幕、擦除、跟踪、抠像、合成、时间线与输出 | 工具接入交工程师；新视觉素材交视觉制作 |
| 救火队员 | 专业职责均不适用的必要交付，如临时资料整理、翻译 | 项目案例与参考研究交锦衣卫；忙碌、离线、缺配置不构成职责空缺；不替代专业负责人 |

## 运行机制

在身份设置中为七个身份指定自动分工角色。每个项目的同一角色只能有一位负责人；设置总控角色后启用受约束派工。锦衣卫的角色键为 `reference_research`，详细约定见 [JINYIWEI.md](JINYIWEI.md)。

1. 总控先检查已有任务、成果和工作登记，再选择交付类型。无需额外调用模型执行机械分派。
2. 专用 `delegate` 请求包含 `work_type` 和跨轮次稳定的 `work_key`，可以省略 `assigned_agent_id`；服务自动映射负责人。显式负责人必须匹配所选角色。
3. 救火队员使用 `general_support`，并提供 `fallback_reason`，说明其他专业职责不适用的原因。专业负责人暂停、未绑定或离线时保留职责；不转为通用支援。
4. 单选智能体保持用户的直接指定。多选需求先交给总控拆分，不向多人复制整份工作。
5. 同一交付的键在整个项目中保持稳定；同一对话中完全相同的内容和输入，即使换请求编号也复用已有工作。重试先检查当前执行凭据，过期执行不能派工。
6. 修改使用 `revise`。待执行修改合并；原任务已运行则顺序接续；再次引用最初的任务会沿修改链找到最新任务。工作登记始终指向最新接续任务。
7. 普通设备任务创建接口不能直接创建受管理的专业任务，避免跳过去重和分工检查；网页直接指定仍保留。

## 协作方式

拆分应基于不同产物，而不是让多人同时“完成整个项目”。网页可拆为参考研究、视觉稿、资产和工程实现；视频可拆为案例研究、新源素材和现有工程的后期处理。参考材料作为输入供专业执行者使用；已有足够参考或方向已明确时无需增加研究或美术审批。

依赖素材、标准尚未交付时，总控先跟踪依赖，不提前派出下游执行。同一文件或时间线顺序交接，独立产物才并行。具体设备能力与连接状态在执行时核验。维护任务保留原有独立幂等机制。

2.6.0 起，独立任务使用 `execution_mode=isolated`，每项任务各有工作目录、执行记录和成果目录。同一智能体可以在不同对话承担独立任务；设备默认同时执行两项专业工作，可配置 1–4 项，总控另有独立工作通道。并发上限属于设备资源，不属于职业身份，不能因此改派救火队员。

修改现有工程使用默认 `shared`，同一项目的写入顺序执行；多个任务会操作同一外部软件或资源时提供一致的 `resource_keys`。进程退出并核实完成记录之后才释放资源，离线、取消或超时本身都不是安全释放的证明。修改接续保留执行范围，并在开工时接入上一项工作的成果附件。

总控的真实安排、执行者的问题与总控的答复显示在原对话中。交接默认最多两轮，可在总控身份设置调整为 0–10 轮。规则清晰时直接执行；有影响成果的疑点才提问，不编造另一身份的台词，不为了凑轮数闲聊，也不把交流变成审批。执行者发问后结束这一轮进程，收到真实答复后接续原任务。答复失败会呈现阻塞，后续真实答复仍能恢复原工作。

## 明确边界

- 职责分类及语义上是否同一工作仍由总控判断，规则不是一个能识别所有改写的语义去重模型。服务强制角色匹配、稳定工作键及相同内容去重，不应宣称可以杜绝所有误分类。
- 资源保护仅覆盖 Hub 托管的任务和正确声明的资源键；无法自动识别所有外部软件内部状态、绕过 Hub 的人工写入或未声明的共享资源。跨软件操作应在派工时明确作用范围。
- 历史任务保留真实负责人和原有记录，不把已完成或执行中的任务冒充新角色的工作。七个身份不代表七路同时执行，实际并发仍受在线设备和算力资源约束。
